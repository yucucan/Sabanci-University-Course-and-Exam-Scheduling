# Course Timetabling Prototype (Draft v0)

Python implementation of "Course Timetabling Model — Draft v0" on a **synthetic** test instance.

> **The data is invented.** Every value in `data/` was generated by `generate_data.py` to test the code. None of it describes Sabancı University. Replace the CSV files with real or anonymized data from the Registrar's Office when it is available.

## Anaconda'da çalıştırma

1. Zip'i açın; `timetabling_prototype` klasörü masaüstünde veya Belgeler'de dursun.
2. **Anaconda Navigator → Jupyter Notebook → Launch.** Tarayıcıda açılan dosya listesinden `timetabling_prototype` klasörüne girin.
3. `run_in_jupyter.ipynb` dosyasını açın ve hücreleri sırayla **Shift + Enter** ile çalıştırın.

Notebook, `model.py`, `validate.py` ve `data/` klasörü **aynı klasörde** olmalı; kod veriyi oradan okur.

**Kendi verinizi koymak:** `data/` içindeki CSV'leri aynı sütun adlarıyla değiştirin (Excel'de "CSV UTF-8" olarak kaydedin). Sonra notebook'ta 3. adımdaki `%run generate_data.py` satırını **çalıştırmayın**, yoksa örnek veri sizinkinin üzerine yazılır.

## Çalıştırma / Run

```
python generate_data.py              # writes data/*.csv
python model.py                      # Option A: minimize unplaced sections
python model.py --objective seats    # Option B: minimize empty seats
python model.py --soft-capacity      # allow rooms smaller than expected enrollment
python validate.py                   # independent check of results/timetable.csv
python diagnose.py --data scenario_tight   # why unplaced, which rules to relax
```

## Dosyalar / Files

| File | What it does |
| --- | --- |
| `generate_data.py` | Creates the synthetic instance (22 sections, 7 rooms, 5 days × 10 hourly slots) |
| `model.py` | Builds the allowed set `A_sk`, the MIP with constraints (1)–(5), solves it, writes results |
| `diagnose.py` | Lists unplaced sections and finds the cheapest set of rule relaxations that places them all |
| `scenario_tight/` | The same instance made harder on purpose (no 120-seat room, INS06 only two mornings) |
| `show_constraints.py` | Lists the constraints in the model, their BRD rows and counts, and how many options each pre-solve rule removes |
| `generate_full_data.py` | Creates `scenario_full/`: a synthetic instance at real scale (654 courses, 1,599 sections, 114 rooms, 5 days x 12 hours) |
| `model_size.py` | Reports how large the model is on a data folder and how much the reduction ideas help; does not solve |
| `validate.py` | Re-checks every rule on the output without using the model code |
| `data/` | Input CSVs, one per data field named by the Registrar's Office |
| `results_optionA/`, `results_optionB/` | Timetable, room utilization and weekly grid for each objective |

## Results on the synthetic instance

| | Option A (unplaced) | Option B (empty seats) |
| --- | --- | --- |
| Sections placed | 22 / 22 | 22 / 22 |
| Validation | All checks passed | All checks passed |
| Solve time | < 1 s | < 1 s |

Option B fills rooms more tightly (occupancy about 89–98% per room vs. 73–83% in Option A), at no cost in placed sections on this instance.

**Stress test:** removing the only 120-seat room leaves 5 large sections unplaced, and the model reports that no feasible (slot, room) pair exists for them, which is the kind of diagnostic BRD-9 asks for.

## Diagnosis: which rules to relax

`diagnose.py` solves twice. First with all rules hard, listing unplaced sections. Then in relax mode: every section must be placed, and the relaxable rules (R3 block clash, R5 instructor unavailable, R6 common hour, R7 fixed time, R12 room too small, C5 same-day sessions) may be broken at the cost in `relaxation_weights.csv`. The solver returns the cheapest set of rule changes.

Physical rules are never relaxed: one class per room per hour, one place per instructor per hour, required equipment.

On `scenario_tight`, 6 of 22 sections are unplaced. Placing all of them requires 7 room-size exceptions (largest available room is 80 seats) and 3 hours of instructor-availability exceptions for INS06 (9 teaching hours, only 6 available hours; the solver may split them over 2 or 3 sessions, the cost is the same). The INS06 exceptions stay even when R5 is made 10 times more costly, so they are unavoidable, not a preference.

**The weights are placeholders.** How costly each relaxation is must come from the Registrar's Office [OPEN].

## Full-scale instance (`scenario_full/`)

Only the three counts come from the Registrar's Office (654 courses, 1,599 sections, 114 classrooms, S2). The time grid (5 days x 12 one-hour slots, 08:00-20:00) is the illustrative assumption of the model document. Everything else is invented: room sizes, 612 instructors, enrollments, 273 academic blocks, unavailability, fixed times.

| | Value |
| --- | --- |
| Sessions | 3,136 (about 2 per section) |
| Teaching hours / room-hours available | 5,013 / 6,612 (76% room use) |
| x variables before filtering | 21,450,240 |
| after filtering | 9,452,206 |
| + only reasonably sized rooms | 4,314,240 |
| two-stage model, stage 1 (time only) | 156,536 |

The single-stage model is far too large to build on a laptop, so `model.py` stops above 1,000,000 variables (override with `--force`). This is the evidence for the next step: a pilot subset or the two-stage model (time first, rooms second).

Simplification: courses with many sections (first-year and university-wide courses) are kept out of academic blocks, because under the strictest block reading of constraint (4) [OPEN] they would block most of the week.

## Not modeled yet ([OPEN] in the model document)

- Co-requisite relations (R10), student clashes outside academic blocks (R15)
- Double-coded courses are expected to be merged into one section in the data
- Constraint (4) uses the strictest academic-block reading; constraint (5) assumes different days
- The real time grid and data format
